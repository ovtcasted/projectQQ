# QR-Service: Система автоматизированного приема и приоритизации заявок

Веб-приложение на базе фреймворка Flask и реляционной базы данных SQLite, предназначенное для мгновенной регистрации технических инцидентов в помещениях с помощью персональных QR-кодов. Система оснащена автономным экспертным модулем классификации текстовых обращений со встроенной базой знаний и изолированным слоем валидации данных.

## Бизнес-ценность и архитектурные преимущества

* Исключение человеческого фактора: Пользователю не требуется проходить регистрацию или вручную указывать локацию. Сканирование QR-кода автоматически связывает заявку с конкретным помещением через GET-параметр.
* Обеспечение безопасности жизнедеятельности: Локальный классификатор содержит слой превентивного анализа угроз. При обнаружении триггеров опасности (искрение, задымление, короткое замыкание) система мгновенно блокирует создание стандартной заявки и выводит экстренную инструкцию по эвакуации и оповещению служб.
* Интегрированная база знаний (Knowledge Base): Модуль ИИ способен дифференцировать регламентные вопросы от реальных поломок. Если пользователь запрашивает справочную информацию, система предоставляет официальную инструкцию из базы знаний (по работе с проекторами, принтерами или ПК), снижая нагрузку на технический персонал.
* Криптографическая защита данных: Для отслеживания статуса заявки без принудительной авторизации генерируется уникальный безопасный токен (secrets.token_urlsafe), хэш которого (SHA-256) сохраняется в базе данных. Это полностью исключает компрометацию данных и просмотр чужих заявок методом перебора ID.
* Автономность и конфиденциальность: Алгоритм анализа текста работает локально на сервере, не совершает внешних сетевых вызовов к API сторонних провайдеров, что гарантирует независимость от интернета и стопроцентную конфиденциальность внутренней информации учреждения.

## Стек технологий

* Backend: Python 3.10+, Flask
* Database: SQLite3 (с фиксацией истории изменений статусов)
* AI/ML: Локальный экспертный NLP-классификатор (Rule-based NLP Classifier, модуль ai_helper.py)
* Security: hashlib (SHA-256), secrets (криптографически стойкая генерация токенов и номеров REQ-XXXXXX)
* Frontend: HTML5, CSS3, Jinja2 (динамическая шаблонизация страниц)
* Infrastructure: ngrok / VPN-туннелирование для обеспечения публичного доступа при тестировании

## Схема основной таблицы базы данных (Tickets)

```text
+-----------------------------------+

|              Tickets              |
+-----------------------------------+

| id (INTEGER, PK, AUTOINCREMENT)   | -- Идентификатор заявки
| public_number (TEXT, UNIQUE, NN)  | -- Номер формата REQ-XXXXXX
| title (TEXT, NOT NULL)            | -- Заголовок (генерирует ИИ)
| description (TEXT, NOT NULL)      | -- Текст проблемы от пользователя
| category_id (INTEGER, FK)         | -- Ссылка на Categories.id
| location_id (INTEGER, FK)         | -- Ссылка на Locations.id
| status (TEXT, DEFAULT 'Новая')    | -- Текущий статус заявки
| created_at (DATETIME, DEFAULT CS) | -- Время создания
| updated_at (DATETIME, DEFAULT CS) | -- Время обновления
| assignee_id (INTEGER, FK)         | -- Ссылка на Users.id (исполнитель)
| tracking_token_hash (TEXT, NN)    | -- SHA-256 хеш токена отслеживания
+-----------------------------------+
```


## Инструкция по развертыванию и запуску

1. Клонирование репозитория:
   git clone <ссылка_на_репозиторий>
   cd projectQQ

2. Установка зависимостей:
   pip install Flask

3. Запуск веб-сервера:
   python app.py
   Сервер запустится в локальном режиме на порту 5000 (http://127.0.0.1:5000).

4. Настройка публичного туннеля для демонстрации:
   В отдельном терминале выполните команду:
   ngrok http 5000
   Скопируйте полученный URL-адрес с протоколом https для удаленного доступа.

## Сценарий демонстрации (валидация функционала)

Для проведения тестирования необходимо использовать публичный URL, полученный из ngrok (далее — <domain>).

1. Автоматическое определение локации через QR:
   Переход по ссылке https://<domain>/create?room=214 инициализирует форму. Идентификатор помещения автоматически связывается с формой через параметр location_id.

2. Валидация типов обращений модулем ИИ (ask_gigachat):
   * Тест безопасности: Ввод текста «Из розетки пошел дым и искры» -> Классификатор определяет тип «Потенциальная опасность», блокирует запись в базу данных во избежание бюрократической задержки и выводит инструкции по экстренной эвакуации.
   * Тест информационной справки: Ввод текста «Как правильно подключить ноутбук к проектору» -> Система определяет тип «Информационный вопрос», извлекает инструкцию из OFFICIAL_KB и выводит ее пользователю на экран без создания тикета на мастера.
   * Тест нехватки данных: Ввод текста «Помогите, не работает» -> Функция validate_user_text и ИИ определяют недостаточную длину/информативность текста и запрашивают конкретизацию проблемы.
   * Тест штатной неисправности: Ввод текста «В кабинете сломался стул и шатается парта» -> ИИ автоматически определяет категорию «Имущество и мебель», формирует короткий заголовок (title) и разрешает отправку формы на роут /submit_ticket.

3. Обработка POST-запроса маршрутом /submit_ticket:
   При успешной валидации и отправке формы на бэкенде выполняются следующие действия:
   * Проверка на дубликаты в рамках локации (validator.py). При обнаружении активного дубликата транзакция прерывается.
   * Генерация публичного номера (REQ-XXXXXX) и безопасного токена.
   * Запись инцидента в таблицу Tickets, запись стартового лога в TicketHistory.
   * Пользователь перенаправляется на success.html, где получает токен для безопасного трекинга.

4. Мониторинг в панели администратора:
   Интерфейс по адресу https://<domain>/admin отображает агрегированный список заявок, с возможностью назначения исполнителя (assignee_id) и изменения текущего статуса с автоматическим логированием изменений в TicketHistory и системный логгер (logger.py).
